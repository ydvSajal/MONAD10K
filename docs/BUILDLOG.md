# Build log

One line per day. Feeds the pitch and build-in-public posts.

- **17 Sep (Day 1)** — Toolchain up (Foundry/Slither/Aderyn/gitleaks in WSL). A1 answered: ERC-8004 is live on Monad testnet (both registries are UUPS proxies); pulled and selector-verified the ABI against deployed bytecode.
- **18 Sep (Day 2)** — Verified the environment instead of trusting docs: P256 precompile at `0x0100` returns 1 for a real signature, and Monad testnet USDC (`0x534b…43A3`) has EIP-3009 with EIP-712 domain name `"USDC"` v2. Shipped `ReceiptRegistry` + `ReceiptRouter` with 18 tests green, including a fork test that pays live agent 1 with a signed authorization. Found and specced a hole in the design: revoked ERC-8004 feedback kept counting forever — now a permissionless `sweepRevoked`.
- **21 Sep (Day 3)** — Passkey kill switch cleared: a software P256 passkey binds an address through `ReviewerRegistry` and verifies via the live `0x0100` precompile on Monad testnet (`bind` ~158k gas). A Copilot review caught a fund-locking edge case in the router (agent wallet set to the router itself) before it reached `main`. `evm_version` moved to cancun after probing `MCOPY` live.
- **23 Sep (Day 4)** — Scoring core lands: `ScoringLib` (21-bucket histogram, log2 payment weight capped at 4, weighted median), `Erc8004Adapter`, and `GroundedReputation.ground` with the full check order, plus the permissionless `sweepRevoked` that removes revoked feedback from the histogram. A fork test runs the whole path against the **live** ERC-8004 registries — pay, giveFeedback, bind, ground — which confirmed feedback indices are 1-based. `ground` costs 353k gas, over the 250k guess: measurement shows 110k of that is four exclusion reads against the ERC-8004 identity proxy, which we do not control.
- **23 Sep (Day 6, read path)** — `Deploy.s.sol` rehearsed end to end on an anvil fork of Monad testnet: four contracts, one broadcast, CREATE-address predictions asserted and held. `@sajalydv/grounded-sdk` reads the grounded score straight from the contract and reports every reason a trust check fails, so an unrated agent is never mistaken for a bad one. A census of the live ERC-8004 registry found 21 teams with agents on 10143 — and that over half of those agents have no payout wallet, so nobody can pay them at all.
- **24 Sep (Day 7, write path)** — `@sajalydv/grounded-sdk` can now do the whole buyer loop: `bindPasskey`, `pay` (approve + `pay`, or one EIP-3009 authorization), and `rate`, which posts the ERC-8004 feedback, reads the index the registry assigned from its event, and grounds it with a passkey signature. Headless agents get a `SoftwareAuthenticator` whose assertions an independent WebAuthn verifier accepts. `rate` dry-runs `ground` before it posts anything, because a public rating that fails to ground is permanent and counts for nothing — the fork test proves an agent owner rating their own agent is refused with no feedback left behind. 18 tests green against the live ERC-8004 registries on an anvil fork.
- **24 Sep (Day 8, 402 flow)** — The buyer loop closes over HTTP: a seller puts `groundedPaywall()` on a route and answers unpaid calls with a 402 naming the router; `withTrust(fetch)` checks the agent against the buyer's policy, pays through the router, and retries with a receipt signed by the payer. On an anvil fork of Monad testnet a trusted agent serves 200 once per receipt, an untrusted one is paid nothing, and a receipt id copied off chain is worthless to anyone but the wallet that paid it. `GroundedGate` gives contracts the same check as a one-line modifier.
- **24 Sep (Day 8, demo seller)** — The 402 flow runs as a real service: on an anvil fork of Monad testnet (our four contracts over the live ERC-8004 registries and USDC), `apps/demo-seller` (Hono) sells `/insight` as agent 1 behind `groundedPaywall`. A buyer using `withTrust(fetch)` got 402, paid 0.05 USDC through the router, and was served 200 on the retry.
- **24 Sep (Day 8, demo buyer)** — Day 8 done-when met. `apps/demo-buyer` is a CLI around `withTrust(fetch)`: on an anvil fork it refused the unrated seller (0 reviewers, nothing paid), paid 0.05 USDC and got 200 under an open policy, then refused the same agent once a paying reviewer grounded a 20 (exit 2, "score 20, policy wants 70"). The raw ERC-8004 summary for that agent read 55 at the same moment, which is the whole point of the project in one number.
- **25 Sep (review fixes)** — Reviewed `main` end to end and fixed what it found, before the testnet deploy while the contracts can still change. `payWithAuthorization` now takes a `ReceiveWithAuthorization` signed to the router with an agent-bound nonce, so a signed payment can no longer be front-run into USDC (paid, no receipt) or relayed to another agent; both attacks are fork-tested against live USDC. `lastOwnerOf` lets `check()` fail an agent sold since its last rating instead of waiting for the next one. `withTrust` re-sends after a paid 402 and hands back the receipt id if the seller never accepts it.
- **26 Sep (Day 9–10, seed + explorer)** — `scripts/seed` plays the demo story on an anvil fork: three freshly registered agents, and the Sybil one reads 87 on ERC-8004 while its grounded score is 20 (two paying reviewers vs ten unpaid wallets); the owner's wash rating is rejected with `ExcludedReviewer`. `apps/web` is now a Next.js explorer (agent list, raw vs grounded, receipts vs rated payments, reviewers) plus `GET /api/v1/agents/:id/score`, reading events straight from the chain until the testnet deploy lets Envio take over. Playground cut to the roadmap.
- **26 Sep (Day 11, docs)** — `/docs` on the explorer: Quickstart, SDK reference, Scoring spec (every constant, with the worked 22/28 example that yields the seeded 20), Contracts, 402 scheme, Threat model, FAQ. Written from the contracts and SDK source, not the TRD, which has drifted (rotation, `paid`, receive-authorization). The Quickstart snippets were run against a fresh seeded fork and print what the page says. Threat model states the limits first: wash rating unsolved, rotation needs no old passkey.
- **26 Sep (Day 12, freeze prep)** — Fresh clone of `main` into a short path: `pnpm install --frozen-lockfile`, build, typecheck, 27 SDK + 64 forge tests, fmt all green; then anvil fork, `Deploy.s.sol`, seed, two sellers, buyer, explorer and docs from that clone. The buyer paid the honest agent (10 to 9.95 USDC) and refused the Sybil one (raw 87, grounded 20) at 0 spent. The run found a Quickstart bug: it never fetched the git submodules, so `forge` failed on a fresh clone. Also: the demo seller stores used receipts in Postgres when `DATABASE_URL` is set (checked against a real Postgres: one winner of 20 concurrent claims, survives a new instance).
- **26 Sep (AI layer)** — `@sajalydv/grounded-mcp`: a read-only MCP server (`grounded_score`, `grounded_check`), tested offline and over real stdio against the seeded fork (Sybil agent: pass false, grounded 20 vs raw 87). `apps/demo-buyer` `agent` mode: a language model, through the Vercel AI SDK on any OpenAI-compatible endpoint, chooses among sellers; the URL allowlist, trust policy and spend cap are code. Checked with a scripted model that tries to buy from the Sybil seller and fetch an off-list URL: neither happened, exactly one 0.05 USDC payment left the wallet. **Not run with a real model** (no key), so no model is claimed as powering anything.
- **26 Sep (audit vs PRD/TRD, hardening)** — Checked the build against every doc; fixed what prototyping skipped. The explorer's log scan is now incremental (one accumulator, only new blocks per refresh, 8 chunks in parallel) instead of rescanning from the deploy block every time, which START-HERE warns about. `/` is a landing page with live counters and the biggest raw-vs-grounded gap, the list moved to `/agents`. The score API has CORS, a 15 s cache and a 60/min/IP limiter (429 verified). `RPC_URL_FALLBACK` finally does something: the SDK takes `fallbackRpcUrl` and wraps both RPCs in viem `fallback`.
- **26 Sep (adversarial tests)** — Nine tests the timeline's 3 Oct item asked for and the suite lacked: exclusion of an approved operator, an operator-for-all and the payout wallet (only the owner was tested), high-`s` malleability at `ground` and `bind`, replay on another chain, a missing UV flag at `ground`, and an expired receipt at `ground` plus its last-second boundary. All pass: the contracts already refused each. `docs/threat-tests.md` maps every named threat to its test or its documented limit.
- **26 Sep (playground)** — `/playground`: create a browser-stored test wallet, get funds from `/api/drip`, create a real WebAuthn passkey and bind it, pay an agent 0.10 USDC by EIP-3009 authorization, rate it, watch the grounded score move. New `BrowserPasskey` in the SDK (ox; folds `s` to low-s). A Playwright test in the installed Chrome with a virtual WebAuthn authenticator (user verification on) runs the whole loop on a fork: the passkey binds through the P-256 precompile, the assertion verifies onchain, and a passkey restored after a reload replaces the first rating. Faucet limits (per address, per IP, 400 on bad input) checked. The page had a phone-width overflow, found by measuring, fixed. Not tried on a hardware passkey or phone.
